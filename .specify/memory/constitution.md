
# WordFinder Constitution

## 1. Code Quality
- Follow SOLID principles where applicable.
- Prefer clean, readable and maintainable code.
- Avoid unnecessary abstractions and complexity.
- Keep public APIs minimal and explicit.

## 2. Architecture
- Follow a library-first approach.
- Keep implementation details encapsulated.
- Separate production code from tests and benchmarks.
- Avoid unnecessary infrastructure and dependencies.

## 3. Performance
- Prioritize algorithmic efficiency.
- Minimize unnecessary memory allocations.
- Consider large input streams.
- Validate performance assumptions through benchmarks.

## 4. Testing
- Use automated unit testing.
- Cover functional requirements and edge cases.
- Ensure deterministic test results.
- All changes must pass the test suite.

## 5. Development Practices
- Follow Spec-Driven Development.
- Define requirements before implementation.
- Document relevant technical decisions.
- Use AI-assisted development responsibly.
- Review and understand all generated code.

## 6. Compatibility
- Respect the public interface defined by the challenge.
- Avoid introducing unnecessary external dependencies.
